# kaleido: rasteriza os gráficos Plotly como imagem pro relatório em PDF
# (core/pdf_report.py). A versão 0.2.1 (usada numa primeira versão deste
# recurso) tem um bug conhecido no Windows: quando o caminho do projeto tem
# espaço (ex.: "Vinicius Bemfica", "Métricas QA"), o subprocesso interno do
# kaleido falha com "--plotlyjs argument is not a valid URL or file path" -
# https://github.com/plotly/Kaleido/issues (Popen com shell=True no Windows
# quebra o path com espaço). kaleido>=1.0 reescreveu essa parte (usa
# choreographer, sem shell=True) e não tem esse problema. Em troca, não vem
# mais com um navegador embutido: se não achar um Chrome/Chromium/Edge/Brave
# já instalado no sistema, baixa um "Chrome for Testing" próprio na primeira
# vez que gera uma imagem (chamada explícita em core/pdf_report.py) e
# reaproveita esse download depois. No Streamlit Community Cloud, esse
# "Chrome for Testing" baixado sozinho falha ao abrir porque o container é
# minimalista e não tem as bibliotecas do sistema (libnss3, libgtk-3-0,
# libasound2 etc.) que QUALQUER Chrome/Chromium precisa pra rodar - por isso
# o arquivo packages.txt (raiz do projeto) instala o pacote "chromium" via
# apt: ele já traz essas bibliotecas junto (como dependência), e o
# kaleido passa a achar e usar esse chromium do sistema direto, sem
# precisar baixar nada.
